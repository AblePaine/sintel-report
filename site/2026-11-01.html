The agent stops waiting to be asked — DeepSeek open-sources its superagent#

  • DeepSeek's Harness team released dsh-superagent-prototype on GitHub on October 31 (MIT, explicitly a research prototype, not an official product): an always-on coding agent scoped to one GitHub repository. A persistent router session turns issues and comments from approved team members into tickets; each ticket is worked by an isolated worker session that replies in the original thread, often with a pull request. It passed 4,000 stars within a day by one count. The catch is in its own docs: worker sessions run with full access as the operator's OS user, and DeepSeek recommends a dedicated OS account — isolation is the operator's problem. DeepSeek's simulated p95 task time (15.7 vs 29.5 minutes for a single-session baseline) is self-reported on synthetic tests; real coding quality was not measured. MarkTechPost · Complete AI Training
  • The architecture is the story, not the benchmark: router-plus-isolated-workers, running on the operator's own machine under an MIT license, is a direct open challenge to hosted coding agents. The capability is going ambient and self-hostable; the unsolved part is the blast radius.

Skill files are an attack surface — and the hiding is now documented at scale#

  • The Grok lane flagged a post claiming SKILL.md files can carry shell commands hidden in Unicode Tag characters (U+E0000–U+E007F), which editors render as nothing. The specific post is a single-account claim, but the technique itself checks out against a much larger dataset: a VirusTotal series analyzing 35,878 agent skills found 6,637 malicious ones — 62% carrying no malicious code at all, the payload written as plain-language instructions — with 90 hiding instructions after blank-line padding, inside HTML comments, or in invisible Unicode. Snyk's earlier ToxicSkills audit separately found prompt injection in 36% of 3,984 public skills. Scanner tools that decode hidden tag text and flag exfiltration patterns already exist. IT Security News / VirusTotal series · ClawdBytes / Snyk audit
  • What a reviewer sees and what the model reads are now provably two different files. That gap — not any single malicious skill — is the durable fact.

MCP stateless — a dating correction, and the cost nobody priced#

  • The Gemini lane reported stateless MCP "hitting production" today. The specification itself is not new: the 2026-07-28 MCP revision removed the initialize handshake and the session ID, making every request self-contained — the largest structural change since launch, and already months old. What is new is the consequence analysis landing now: with server-sent-event resumability gone, a dropped connection loses the in-flight request, and a client that retries an action tool (send, charge, publish) can execute it twice. Cloudflare's portal layer now supports the stateless revision alongside legacy clients, which is adoption plumbing, not a new spec. PostMCP analysis, November 1 · DEV — spec explainer
  • Statelessness also cuts the other way for self-hosters: a stateless MCP server is an ordinary HTTP endpoint. No serverless platform is required to benefit — a container behind a reverse proxy on owned hardware qualifies.

Edge signal of the day#

  • The gate moved from capability to access. Look at where the fights were this weekend: Amazon deciding whether Muse may buy, Anthropic deciding what Claude may reverse-engineer, banks deciding whether an agent may log in and who pays when it acts, Moonshot deciding what open weights are allowed to know, and a skill ecosystem discovering that what humans review is not what models read. None of these are capability stories — the models are already capable enough to be worth gating. The scarce, contested layer is now permission: who may act, through which door, under whose rules, at whose toll. Every gate is a tax on the rented, hosted, platform-mediated path — and a relative gain for the surfaces no gatekeeper sits on: weights on owned hardware, storefronts and APIs that are directly callable, skills that can be scanned before they are trusted, and files that never leave the machine. The edge is not getting through the gates fastest. It is needing fewer of them.
